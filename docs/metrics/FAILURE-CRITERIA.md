# Failure-criteria detectors

BK-12 operationalizes every charter section 14 failure with a declared tolerance, window, comparator, and evidence requirement:

1. useful behavior does not exceed primitive or fixed-feature controls
2. abstraction count rises while marginal utility approaches zero or becomes negative
3. option models increase planning error or computation without compensating gain
4. old abstractions are protected by stale credit while useful new ones are rejected
5. the feature population collapses to redundant or trivial correlates
6. adaptation degrades toward or below the linear or tabular diagnostic baseline with age
7. hidden replay, offline updates, privileged labels, or undeclared compute affect results
8. resource compliance depends on omitted or unsupported measurements
9. the run cannot be reproduced within declared statistical and platform tolerances
10. claimed open-endedness disappears when compute, memory, or population size is held fixed

Unavailable evidence, missing comparators, or missing required signals yield `indeterminate`, never pass. Failure is a valid scientific result.

The committed fixture at `fixtures/failure-criteria/v1/expected-outcomes.json` contains one positive, one negative, and one unavailable case per criterion.
